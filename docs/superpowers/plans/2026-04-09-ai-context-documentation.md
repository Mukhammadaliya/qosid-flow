# Domain Glossary

Quick reference for domain-specific terms used throughout the qosid-flow codebase.

| Term | Definition |
|------|-----------|
| **Biruni** | Oracle DB wrapper REST API. The project's data source for pulling requests and saving responses. Accessed via `BiruniClient.java` using HTTP Basic Auth. |
| **CompanyId** | Multi-tenant identifier. Every request belongs to a specific company. Used together with RequestId to form a Composite Key. |
| **Composite Key** | `{companyId}:{requestId}` — unique identifier for a request across Redis state, locks, and Kafka messages. Generated by `getCompositeId()` method. |
| **Pipeline Stage (E1-E5)** | The 5-stage request processing flow: E1 (Oracle Pull) -> E2 (Kafka Produce) -> E3 (Consumer + Redis Lock) -> E4 (HTTP + Circuit Breaker) -> E5 (Save to Oracle). |
| **E1: Oracle Pull** | `RequestPuller.java` — scheduled polling of requests from Biruni every 5 seconds. |
| **E2: Kafka Produce** | `RequestProducer.java` — sends pulled requests to `gateway.request.new` Kafka topic. |
| **E3: Consumer Process** | `RequestConsumer.java` — consumes from Kafka with idempotency check and distributed lock. |
| **E4: HTTP Request** | `HttpRequestService.java` — sends HTTP requests to external APIs with Circuit Breaker and OAuth2. |
| **E5: Oracle Save** | `ResponseConsumer.java` — saves HTTP responses back to Oracle/Biruni with retry logic. |
| **DLQ** | Dead Letter Queue — Kafka topic `gateway.request.dlq` where failed messages go after all retries are exhausted. Triggers Telegram alert via `DlqConsumer.java`. No auto-replay by design. |
| **CB (Circuit Breaker)** | Resilience4j Circuit Breaker — per-domain instances that protect external APIs. 3 states: CLOSED (normal), OPEN (blocking all requests), HALF_OPEN (testing recovery). |
| **RedPanda** | Kafka-compatible message broker used in local development (Docker). Production may use Apache Kafka directly. |
| **Request Status** | Lifecycle: `N` (New) -> `P` (Processing) -> `S` (Sent) -> `C` (Completed) / `F` (Failed). Defined in `RequestStatus.java` enum. |
| **ErrorSource** | Enum indicating where an error originated: `HTTP` (external API), `SYSTEM` (internal error). Defined in `ErrorSource.java`. |
| **Protected Zone** | Source files containing production-critical logic (idempotency, locking, retry, ack) that require extra caution before modification. See `SAFETY-RULES.md`. |
| **Safe Zone** | Source files that can be freely modified: `TestController.java`, `infrastructure/`, `application.yml` (adding config), new Properties classes, documentation. |
| **Manual Ack** | Kafka acknowledgment mode where messages are acknowledged only after successful processing, not automatically. Prevents message loss. Set in `KafkaConfig.java`. |
| **Idempotency** | Guarantee that processing the same message multiple times produces the same result. Implemented via Redis state check (`isCompleted`) + distributed lock (`tryLock`) in `RequestConsumer.java`. |
| **Backpressure** | Mechanism to slow down message processing when the HTTP thread pool is full. Implemented via `CallerRunsPolicy` in `ThreadPoolConfig.java`. |
| **CallerRunsPolicy** | Thread pool rejection policy that runs the task in the caller's thread instead of rejecting it. Provides natural backpressure. |
| **Safety Net** | `Integer.MAX_VALUE` returned by `RequestStateService.getAttemptCount()` when Redis is unavailable. Prevents infinite retry loops by making the attempt count always exceed max retries. |
| **OAuth2 Provider** | External authentication service configuration fetched from Oracle. Supports pluggable providers via `OAuth2Client` interface. Currently implements Biruni type. |
| **Dynamic Concurrency** | Automatic adjustment of Kafka consumer thread count based on consumer lag. Monitored every 10s by `ConcurrencyMonitorService.java`, adjusted by `DynamicConcurrencyManager.java`. |
```

     |   E1: Pull     E2: Produce  |   E3: Consume   E4: HTTP   |   E5: Save
     |   (5s poll)    (async)       |   (+ Redis)     (+ CB)     |   (+ retry)

                                    |    RequestConsumer -------->+
                                    |         |                   |
                                    |    (idempotency check)      |
                                    |    (distributed lock)       |
                                    |         |                   |
                                    |    HttpRequestService ----->+  (Circuit Breaker)
                                    |         |                   |  (OAuth2 if needed)
                                    |         v                   |
                                    |    gateway.request.response |
                                    |         |                   |
                                    |    ResponseConsumer --------+----> Oracle/Biruni
                                    |                             |     (save response)
                                    |                             |

                                    |                             |

                                    |                             |

## Stage Breakdown

### E1: Oracle Pull — `RequestPuller.java`

| Aspect | Detail |
|--------|--------|
| **Trigger** | `@Scheduled(fixedDelayString = "${gateway.polling.interval-ms:5000}")` |
| **Condition** | `@ConditionalOnProperty(name = "gateway.polling.enabled", havingValue = "true")` |
| **Input** | HTTP GET to Biruni API (`/b/biruni/bmb/requests$pull`) |
| **Output** | List of `RequestMessage` objects |
| **Validation** | `RequestValidator.validate()` — checks companyId, requestId, baseUrl, method |
| **On Failure** | Logs error, increments `oraclePullError` metric |
| **Flow** | Pull -> Validate each -> Send valid ones to E2 -> DLQ invalid ones |

### E2: Kafka Produce — `RequestProducer.java`

| Aspect | Detail |
|--------|--------|
| **Input** | `RequestMessage` from E1 |
| **Output** | Message sent to `gateway.request.new` Kafka topic |
| **Key** | `compositeId` (companyId:requestId) for partition affinity |
| **Retry** | 3 attempts, 3s interval (in `RequestPuller.sendToKafkaWithRetry`) |
| **On Failure** | After retries exhausted, sends to DLQ |

### E3: Consumer Process — `RequestConsumer.java`

| Aspect | Detail |
|--------|--------|
| **Trigger** | `@KafkaListener(id = "requestConsumer", topics = "${gateway.kafka.topics.request-new}")` |
| **Container Factory** | `requestConsumerFactory` with MANUAL ack, dynamic concurrency |
| **Idempotency** | 1. Check `requestStateService.isCompleted(key)` — skip if done |
| | 2. Try `requestStateService.tryLock(key)` — skip if locked |
| **Processing** | Submit to `httpExecutor` thread pool -> call E4 |
| **Ack** | Manual acknowledgment after async task submitted |
| **On Failure** | Check attempt count -> retry or send to DLQ |

### E4: HTTP Request — `HttpRequestService.java`

| Aspect | Detail |
|--------|--------|
| **Input** | `RequestMessage` from E3 |
| **Output** | `ResponseMessage` sent to `gateway.request.response` topic |
| **Circuit Breaker** | Per-domain Resilience4j CB. If OPEN, returns 503 immediately. |
| **OAuth2** | If `oauth2Provider` set, fetches token via `OAuth2ProviderService` and adds `Authorization` header |
| **Timeouts** | Default: connect 10s, read 30s. Per-endpoint overrides via `gateway.http.endpoint-timeouts` |
| **On Success** | Records CB success, sends ResponseMessage to response topic |
| **On Failure** | Records CB failure, checks if retryable (408, 429, 5xx) |

### E5: Oracle Save — `ResponseConsumer.java`

| Aspect | Detail |
|--------|--------|
| **Trigger** | `@KafkaListener(id = "responseConsumer", topics = "${gateway.kafka.topics.request-response}")` |
| **Container Factory** | `responseConsumerFactory` with MANUAL ack |
| **Input** | `ResponseMessage` from Kafka |
| **Output** | HTTP POST to Biruni API (`/b/biruni/bmb/requests$save`) |
| **Retry** | `saveWithRetry()` — max 3 attempts, 3s interval |
| **On Failure** | After retries, saves error response to Oracle |
| **Ack** | Manual acknowledgment after save attempt |

## Cross-Cutting Concerns

### Circuit Breaker (Resilience4j)

- **Scope:** Per-domain (extracts domain from `baseUrl` for CB instance name)
- **Sliding Window:** 10 calls
- **Failure Rate Threshold:** 50% -> triggers OPEN
- **Slow Call Threshold:** >10s duration, >50% rate -> triggers OPEN
- **OPEN Duration:** 30s before transitioning to HALF_OPEN
- **HALF_OPEN:** 3 permitted test calls
- **OAuth2 errors excluded:** Token failures do not count toward CB failure rate
- **Config class:** `resilience4j.circuitbreaker.configs.default.*` in `application.yml`

### Idempotency (Redis)

- **State Key:** `request:state:{companyId}:{requestId}` (TTL: 72 hours)
- **Lock Key:** `request:lock:{companyId}:{requestId}` (TTL: 300 seconds)
- **Dual Check:**
  1. `isCompleted(key)` — if status is COMPLETED or FAILED, skip (already processed)
  2. `tryLock(key)` — Redis `SET NX` with TTL. If fails, another instance is processing it
- **Safety Net:** If Redis unavailable, `getAttemptCount()` returns `Integer.MAX_VALUE` to prevent infinite retries
- **Managed by:** `RequestStateService.java`

### Dynamic Concurrency Scaling

- **Monitor:** `ConcurrencyMonitorService` checks Kafka consumer lag every 10s
- **Manager:** `DynamicConcurrencyManager` adjusts consumer thread count
- **Range:** min 3 (default) to max 15 threads
- **Scale Step:** +/- 2 threads per adjustment
- **Cooldown:** 30s minimum between scaling events
- **Threshold:** Scale up when lag > 50, scale down when lag < 10
- **Scope:** Request and Response consumers scaled independently

### Thread Pool & Backpressure

- **HTTP Executor:** Separate thread pool for HTTP requests (`httpRequestExecutor`)
- **Core Size:** `minConcurrency` (default 3)
- **Max Size:** `maxConcurrency * 2` (default 30)
- **Queue:** 50 tasks
- **Rejection Policy:** `CallerRunsPolicy` — when queue full, caller thread runs the task (natural backpressure)

## Request Status Lifecycle

```
N (New)         Created in Oracle, waiting to be pulled
    |
    v
P (Processing)  Pulled by gateway, being processed
    |
    v
S (Sent)        HTTP request sent to external API
    |
    +--> C (Completed)   Success response (2xx)
    |
    +--> F (Failed)      Error after all retries exhausted
```

Enum: `RequestStatus.java` with values `NEW("N")`, `PROCESSING("P")`, `SENT("S")`, `COMPLETED("C")`, `FAILED("F")`
```

## Class Annotations Pattern

**Service/Component classes:**
```java
@Slf4j
@Service  // or @Component
@RequiredArgsConstructor
public class MyService {
    private final SomeDependency dependency;
    // ...
}
```

**Properties classes:**
```java
@Getter
@Setter
@Configuration  // or @Component
@ConfigurationProperties(prefix = "gateway.my-feature")
public class MyFeatureProperties {
    private String someValue = "default";
    private int someNumber = 10;

    @PostConstruct
    public void validate() {
        // validate required fields
    }
}
```

**Kafka consumer classes:**
```java
@Slf4j
@Service
public class MyConsumer {
    // Constructor injection (no @RequiredArgsConstructor due to @Qualifier usage)
    private final SomeDependency dependency;

    @KafkaListener(
        id = "myConsumer",
        topics = "${gateway.kafka.topics.my-topic}",
        containerFactory = "myConsumerFactory"
    )
    public void consume(ConsumerRecord<String, MyMessage> record, Acknowledgment ack) {
        try {
            // process
        } finally {
            ack.acknowledge();  // ALWAYS acknowledge
        }
    }
}
```

## Dependency Injection

**DO:**
```java
@RequiredArgsConstructor
public class MyService {
    private final DependencyA depA;
    private final DependencyB depB;
}
```

**DO NOT:**
```java
public class MyService {
    @Autowired  // NEVER use field injection
    private DependencyA depA;
}
```

**Exception:** When `@Qualifier` is needed (e.g., `RequestConsumer` with `httpRequestExecutor`), use explicit constructor:
```java
public class MyService {
    private final ThreadPoolTaskExecutor executor;

    public MyService(@Qualifier("httpRequestExecutor") ThreadPoolTaskExecutor executor) {
        this.executor = executor;
    }
}
```

## Logging

**Annotation:** Always use `@Slf4j` (Lombok)

**Format:** `"Stage - Action: detail, key={}", value`

```java
// Good
log.info("E1 - Pull completed: requests={}, duration={}ms", count, duration);
log.warn("E3 - Skipped duplicate: key={}", compositeId);
log.error("E4 - HTTP request failed: url={}, status={}, error={}", url, status, e.getMessage());

// Bad
log.info("Processed " + count + " requests");  // String concatenation
log.info("Done");  // No context
```

**Log levels:**
- `DEBUG` — detailed processing steps, state transitions
- `INFO` — stage completions, summaries, configuration loaded
- `WARN` — skipped duplicates, lock failures, retries, circuit breaker state changes
- `ERROR` — unrecoverable failures, DLQ sends, exception details

## Error Handling

1. **Try-catch only when recovery is possible:**
```java
// Good — recovery by sending to DLQ
try {
    sendToKafka(request);
} catch (Exception e) {
    sendToDlq(request, e.getMessage());
}

// Bad — catch just to log and rethrow
try {
    process();
} catch (Exception e) {
    log.error("Error", e);
    throw e;  // pointless wrapping
}
```

2. **Domain-specific exceptions:** Create specific exception types (e.g., `OAuth2TokenException`)

3. **Catch-all only in top-level consumers:** `RequestConsumer` and `ResponseConsumer` catch `Exception` at the top level to ensure Kafka ack and prevent consumer death

## Metrics

**All metrics are centralized in `GatewayMetrics.java`.** Never create metrics in any other file.

**Naming pattern:** `gateway.{stage}.{action}.{type}`

Examples:
- `gateway.oracle.pull.duration` (Timer)
- `gateway.http.request.total` (Counter with tags)
- `gateway.kafka.consumer.lag` (Gauge)

**To add a new metric:**
1. Add field in `GatewayMetrics.java`
2. Initialize in constructor with `meterRegistry`
3. Create accessor method if needed
4. Update Grafana dashboard in `infrastructure/dashboard_grafana.json`

Use Lombok annotations consistently:

```java
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor

    private Long id;
    private String name;
}
```

For Kafka messages, use `@JsonProperty` for snake_case JSON mapping:
```java

@Builder

    @JsonProperty("company_id")

## Anti-Patterns (Never Do)

| Anti-Pattern | Correct Approach |
|-------------|-----------------|
| `@Autowired` field injection | Constructor injection via `@RequiredArgsConstructor` |
| Static utility methods | Instance methods in `@Component` classes |
| God classes (>300 lines) | Split by responsibility into separate classes |
| Metrics outside `GatewayMetrics` | Always add to `GatewayMetrics.java` |
| Hardcoded config values | Use `*Properties.java` + `application.yml` |
| `AUTO` Kafka ack mode | Always `MANUAL` — acknowledge after processing |
| Swallowing exceptions silently | Log or handle; never empty catch blocks |

```markdown
# Safety Rules

Critical rules that prevent AI tools from breaking production systems. Read this file before modifying any core pipeline code.

## NEVER DO — Absolute Rules

These actions will break production reliability. Never do them regardless of context.

### 1. Never remove or simplify idempotency logic in `RequestConsumer.java`

The dual-check pattern (`isCompleted` + `tryLock`) prevents duplicate request processing during Kafka rebalances and multi-instance deployments. Removing either check causes duplicate HTTP requests to external APIs.

### 2. Never reduce Redis lock TTL in `RequestStateService.java`

Lock TTL (default 300s) must exceed the maximum possible HTTP request duration. Reducing it causes concurrent processing of the same request by multiple instances.

### 3. Never remove metrics from `GatewayMetrics.java`

All 54 metrics are used by Prometheus alert rules and Grafana dashboards. Removing any metric breaks monitoring and alerting, making production issues invisible.

### 4. Never change MANUAL ack to AUTO in `KafkaConfig.java`

Manual acknowledgment ensures messages are only acknowledged after successful processing. AUTO ack causes message loss when processing fails — the message is already acknowledged and won't be redelivered.

### 5. Never bypass Circuit Breaker in `HttpRequestService.java`

The Circuit Breaker protects external APIs from being overwhelmed during outages. Bypassing it causes cascading failures: the gateway floods a failing API, which makes recovery slower for both systems.

### 6. Never remove retry logic in `ResponseConsumer.java`

The `saveWithRetry()` method handles transient Oracle/Biruni failures. Without it, a single network glitch causes permanent data loss — the HTTP response is lost and never saved to Oracle.

### 7. Never alter DLQ flow in `DlqConsumer.java` / `RequestProducer.java`

The Dead Letter Queue is the last safety net for failed messages. Altering the flow (e.g., auto-replay, filtering) can cause infinite retry loops or silent message loss.

### 8. Never remove the `Integer.MAX_VALUE` safety net

In `RequestStateService`, `getAttemptCount()` and `incrementAttempt()` return `Integer.MAX_VALUE` when Redis is unavailable. This ensures retry logic always thinks max retries are exceeded, preventing infinite retry loops when Redis is down.

### 9. Never replace `CallerRunsPolicy` in `ThreadPoolConfig.java`

`CallerRunsPolicy` provides natural backpressure: when the HTTP thread pool queue is full, the caller thread (Kafka consumer) processes the request itself, naturally slowing down consumption. Replacing with `AbortPolicy` or `DiscardPolicy` causes request loss or exceptions.

---

## Protected Zones

These files contain production-critical logic. Before modifying any of them, run through the Required Checklist below.

| File | Critical Logic | Risk if Broken |
|------|---------------|----------------|
| `RequestConsumer.java` | Idempotency check + distributed lock + manual ack + async HTTP delegation | Duplicate processing, message loss, thread pool exhaustion |
| `ResponseConsumer.java` | Retry logic + Oracle save + manual ack + error response fallback | Response data loss, Oracle inconsistency |
| `HttpRequestService.java` | Circuit Breaker + OAuth2 token injection + per-endpoint timeouts | Cascading failures, auth failures, timeout mismatches |
| `RequestStateService.java` | Redis state CRUD + distributed lock (tryLock/releaseLock) + Integer.MAX_VALUE safety | Duplicate processing, infinite retries, state corruption |
| `KafkaConfig.java` | Topic creation + consumer factories + MANUAL ack mode + error handlers | Message loss, consumer misconfiguration, missing topics |
| `OAuth2TokenRedisCache.java` | Distributed token lock + cache with TTL + fallback on Redis failure | Token race conditions, auth failures, Redis lock leaks |

## Required Checklist

Before modifying **any** Protected Zone file, verify all of these:

- [ ] **Idempotency preserved?** — Does the change maintain the dual-check pattern (isCompleted + tryLock)? Can the same message be safely reprocessed?
- [ ] **Retry logic correct?** — Are retry counts, intervals, and retryable status codes preserved? Is there still a DLQ fallback after max retries?
- [ ] **Metrics updated?** — If adding new code paths, are corresponding metrics recorded in `GatewayMetrics.java`? Are existing metrics still triggered?
- [ ] **DLQ fallback present?** — Do all failure paths eventually lead to either successful processing or DLQ? No silent drops?
- [ ] **Redis unavailable scenario?** — What happens if Redis is down? Does the code degrade gracefully? Is the Integer.MAX_VALUE safety net preserved?
- [ ] **Manual ack preserved?** — Is Kafka message acknowledgment still manual and happening at the right time (after processing, not before)?
- [ ] **Thread safety?** — If touching concurrent code, are shared resources properly synchronized? Are locks released in finally blocks?
