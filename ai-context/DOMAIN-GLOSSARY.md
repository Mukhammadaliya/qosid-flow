# Domain Glossary

Quick reference for domain-specific terms used throughout the qosid-flow codebase.

| Term | Definition |
|------|-----------|
| **Biruni** | Oracle DB wrapper REST API. The **reference implementation** of the source-integration contract — the original source system qosid-flow pulls requests from and saves responses to. Accessed via `SourceClient` (the generic source connector). qosid-flow depends on the CONTRACT (see "Source-integration contract"), not on the Biruni project. |
| **SourceClient** | The generic source-system connector in `oracle/` (renamed from the former Biruni-named class; package unchanged). Implements `RequestSourceClient` + `ResponseSinkClient` — pulls pending requests (E1) and saves responses back (E5) over HTTP against the UI-configured `gateway.source.*` endpoints. The reference implementation of the source-integration contract. |
| **JsonBodyOAuth2Client** | OAuth2 `client_credentials` client that posts a JSON body to the token endpoint (vs `StandardOAuth2Client`'s RFC 6749 form-urlencoded). Renamed from the former Biruni-named client; `getName()` still returns `"biruni"` (a frozen provider-type value — see "OAuth2 Provider"). Used by BOTH per-request forwarding and the source channel. |
| **Source-integration contract** | The REST endpoints + JSON shapes qosid-flow expects from any source system in PULL mode (pull array, save array, OAuth2 provider-data, tenant field). Specified in `ai-context/SOURCE-INTEGRATION-CONTRACT.md`. Any system exposing these endpoints (bmb-style tables/REST) can use qosid-flow; Biruni is the reference implementation. |
| **TenantId** | Internal multi-tenant identifier (was `companyId`). Every request belongs to a specific tenant. Used together with RequestId to form a Composite Key. At the Biruni boundary it is translated to/from the configured wire field name (default `company_id`) by `TenantMappingService` — see "Tenant boundary translation" in `ARCHITECTURE.md`. |
| **ExtraTenantId** | Internal secondary tenant identifier (was `filialId`), e.g. branch/filial. Optional — may be `null`; NOT part of the composite key or Redis state/lock keys. Wire field name is configurable, default `filial_id`. |
| **Composite Key** | `{tenantId}:{requestId}` — unique identifier for a request across Redis state, locks, and Kafka messages. Generated by `getCompositeId()` method. Format unchanged across the C-faza rename (no migration needed). |
| **Pipeline Stage (E1-E5)** | The 5-stage request processing flow: E1 (Oracle Pull) -> E2 (Kafka Produce) -> E3 (Consumer + Redis Lock) -> E4 (HTTP + Circuit Breaker) -> E5 (Save to Oracle). |
| **E1: Oracle Pull** | `RequestPuller.java` — scheduled polling of requests from Biruni every 5 seconds. |
| **E2: Kafka Produce** | `RequestProducer.java` — sends requests to source-specific Kafka topics (`gateway.oracle.request` or `gateway.api.request`). |
| **E3: Consumer Process** | `OracleRequestConsumer` / `ApiRequestConsumer` — consumes from Kafka with idempotency check and distributed lock. Each has its own topic and thread pool. |
| **E4: HTTP Request** | `HttpRequestService.java` — sends HTTP requests to external APIs with Circuit Breaker and OAuth2. |
| **E5: Response Processing** | `OracleResponseConsumer` (Biruni save + RocksDB) / `ApiResponseConsumer` (RocksDB + callback). |
| **DLQ** | Dead Letter Queue — separate topics per flow (`gateway.oracle.dlq`, `gateway.api.dlq`). Triggers Telegram alert via `OracleDlqConsumer` / `ApiDlqConsumer`. No auto-replay by design. |
| **CB (Circuit Breaker)** | Resilience4j Circuit Breaker — per-domain instances that protect external APIs. 3 states: CLOSED (normal), OPEN (blocking all requests), HALF_OPEN (testing recovery). |
| **Parked (CB park)** | A CB-blocked message held in gateway memory by `CbRequeueScheduler` until its circuit accepts traffic again, then produced back to its request topic. Its Kafka offset stays uncommitted for the whole wait, so **consumer lag rising while a circuit is open is expected**. Give-up is by time (`gateway.retry.max-message-age-ms`), and the park is bounded per flow by `cb-max-pending` / `cb-max-pending-bytes`. Replaced the immediate re-queue that DLQ'd 212 live requests on 2026-07-27 — see SAFETY-RULES rules 23 and 40. |
| **RedPanda** | Kafka-compatible message broker used in local development (Docker). Production may use Apache Kafka directly. |
| **Request Status** | Lifecycle: `N` (New) -> `P` (Processing) -> `S` (Sent) -> `C` (Completed) / `F` (Failed). Defined in `RequestStatus.java` enum. |
| **ErrorSource** | Enum indicating where an error originated: `HTTP` (external API), `SYSTEM` (internal error), `CIRCUIT_BREAKER` (CB rejected), `OAUTH2` (token failure). Defined in `ErrorSource.java`. |
| **Protected Zone** | Source files containing production-critical logic (idempotency, locking, retry, ack) that require extra caution before modification. See `SAFETY-RULES.md`. |
| **Safe Zone** | Source files that can be freely modified: `TestController.java`, `infrastructure/`, `application.yml` (adding config), new Properties classes, documentation. |
| **Manual Ack** | Kafka acknowledgment mode where messages are acknowledged only after successful processing, not automatically. Prevents message loss. Set in `KafkaConfig.java`. |
| **Idempotency** | Guarantee that processing the same message multiple times produces the same result. Implemented via Redis state check (`isCompleted`) + distributed lock (`tryLock`) in all request consumers. |
| **Backpressure** | Mechanism to slow down message processing when the HTTP thread pool is full. Implemented via `RejectWithLogging` in `ThreadPoolConfig.java` — rejected tasks are re-queued to Kafka. |
| **RejectWithLogging** | Thread pool rejection policy that throws `RejectedExecutionException`. Consumer catches it and re-queues to Kafka. Replaced `CallerRunsPolicy` which was blocking consumer threads. |
| **Safety Net** | `Integer.MAX_VALUE` returned by `RequestStateService.getAttemptCount()` when Redis is unavailable. Prevents infinite retry loops by making the attempt count always exceed max retries. |
| **OAuth2 Provider** | External authentication service configuration fetched from Oracle. Supports pluggable providers via `OAuth2Client` interface. Implemented types: `biruni` (`JsonBodyOAuth2Client`, JSON-body token endpoint — the type value `"biruni"` is frozen: it is matched against the Oracle `bmb_oauth2_providers.type` column) and `standard` (`StandardOAuth2Client`, RFC 6749 form-urlencoded `client_credentials`, e.g. Regos `auth.regos.uz`). |
| **Dynamic Concurrency** | Automatic adjustment of Kafka consumer thread count based on consumer lag. Monitored every 10s by `ConcurrencyMonitorService.java`, adjusted by `DynamicConcurrencyManager.java`. |
| **BiruniUpload** | HTTP header (`BiruniUpload: param\|alone`) that signals a multipart file upload. `param` mode: JSON param + file parts. `alone` mode: file only. ProxyController parses multipart, uploads to S3, replaces `\u0000X` placeholders with SHA in param. |
| **S3 Fallback** | When S3 upload fails after 3 retries, ProxyController switches to multipart forwarding with `BiruniUpload` header — Biruni processes files via `runFileUploadParam()` and saves to `biruni_filespace` DB table (`store_kind='D'`). |
| **files Header** | HTTP header containing JSON array of file metadata (`file_name`, `content_type`, `file_size`, `sha`, `store_kind`, `bucket`). Biruni's `OracleHeader.getFiles()` reads this in the `run()` path to pass file info to Oracle procedures. Used when S3 upload succeeds. |
| **FilePart** | Inner class of `RequestMessage` carrying raw file bytes for multipart DB fallback. Fields: `fieldName`, `fileName`, `contentType`, `data`. Only populated when S3 upload fails. |
| **Hop-by-hop Headers** | HTTP headers that must not be forwarded by proxies: `host`, `connection`, `keep-alive`, `transfer-encoding`, etc. Filtered in `ProxyController.extractHeaders()` via `HOP_BY_HOP_HEADERS` set. Forwarding `host` caused Tomcat 500. |
| **S3 Mock** | Node.js server (`tools/s3-mock/s3-mock.js`) that emulates S3 API on port 9000. Files stored in `tools/s3-mock/s3-data/` with SHA as filename. Used for local development instead of a real S3 backend. |
| **Defensive Decompression** | `HttpRequestService.decompressIfNeeded(body, headers)` — inspects the upstream response `Content-Encoding` and decompresses `gzip`/`deflate`/`x-gzip` in userspace. Applied on both the success path and the `WebClientResponseException` error path so `/result` always serves plain bytes. Added in v1.0.5 after reactor-netty `.compress(true)` was found broken with Cloudflare-proxied upstreams. |
| **Accept-Encoding Stripping** | `ProxyController` adds `accept-encoding` to `HOP_BY_HOP_HEADERS` so the forwarded upstream request never asks for compression. Added in v1.0.6 because clients like Postman send `gzip, deflate, br` by default; Cloudflare over HTTP/1.1 then returned partially-encoded bytes that no decompressor could recover. qosid-flow's own outbound `/result` is still compressed by Tomcat based on the **client's** Accept-Encoding. |
| **Placeholder Forms** | `ServletFileUploadEntity.replacePlaceholder` matches two wire forms of the SHA placeholder: plain JSON `"\u0000<index>"` (`JSON.stringify` default) and JSON-string-wrapped `\"\\u0000<i>\"` (escaped for a JSON-string-encoded outer wrapper). Both map to the same replacement so direct-smartup24 curls work via qosid-flow with only the URL changed. |
| **settings-core** | Shared Maven module (`qosid-settings-core`, package `uz.greenwhite.qosid.settings`) holding the single source of settings code used by BOTH JVMs: `SettingsRegistry`, `SettingsCipher` (POJO AES-GCM), `SettingsRepository`, `AdminAccountRepository`, `LoginRateLimiter`, `LoginHandoffRepository`, `settings-schema.sql`. The repo root is the `qosid-parent` reactor: `settings-core` + `app` + `ops`. |
| **Stop-to-edit** | D-loyiha settings model: sozlamalar FAQAT gateway JVM to'xtatilganda tahrirlanadi — gateway'ning barcha sozlama-PUT'lari `409 {"error":"stop-required"}`, yozuv esa ops sidecar'ning `PUT /ops/api/settings/{key}` orqali (gateway UP bo'lsa `409 {"error":"service-running"}`). Har o'zgarish keyingi start'da qo'llanadi — eski `restartPending` oqimi olib tashlangan. |
| **Login-token handoff** | Avto-ulanish bridge: authenticated operator `POST /ops/api/handoff` orqali bir-martalik token oladi (60s TTL, DB'da faqat SHA-256 hash, `login_handoff` jadvali), SPA uni gateway'ning `POST /qosid/admin/api/login-token`iga almashtirib yangi admin sessiya oladi — ops orqali start'dan keyin login sahifasiz davom etish uchun. |
